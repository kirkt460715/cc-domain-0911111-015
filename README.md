# 清账 企业应收核对

维护应收、付款、贷项、核销、争议和关闭期间，并提供账龄、对账单和投递记录。不同币种分别计算；已发送成品有独立摘要，不应由当前余额替代。

## 冻结队列（vintage / cohort）

催收分析按**首次入列**的应收发票冻结队列，新发票不会混入旧队列。每个队列逐月追踪到期、现金回款、贷项、部分/全额核销、核销撤销、争议、单据冲销与结清：

- **双时点**：每个事件同时记录业务日期（`effective`/`issued`/`opened`）与知识日期（`recorded`）。冻结时分别给出业务截止和知识截止；迟到入账不能穿越更早的观察时点，观察期内未到终点的成员按右删失处理。
- **路径守恒**：各币种独立成组，任一观察点均满足「剩余敞口 + 累计回款 + 贷项 + 核销损失 + 单据冲销损失 = 原始金额」。核销与冲销计入损失桶，绝不计入现金回收。
- **回收曲线**：逐月给出风险集（尚未到达终点的成员）、竞争终点事件金额（回款/贷项/核销/冲销）和右删失笔数。
- **冻结版本**：同一队列可多次冻结为不同版本，`vintage.compare` 区分迟到知识（行为变化）与撤销更正（历史更正），`vintage.trace` 可追到具体的核销/撤销记录。

## 运行环境

使用 Python 3.11，核心功能依赖标准库和 SQLite。演示和测试只使用本地合成数据，不需要账户、设备或外部运行服务。请从项目根目录执行命令。

## 检查与运行

构建检查验证语法，测试使用临时数据目录，不会连接远端服务。

```sh
python3 -m compileall -q receivables
python3 -m unittest discover -s tests -v
python3 -m receivables demo
```

演示会展示产品的实际数据处理和输出，运行结束自行退出。查看现有接口：

```sh
python3 -m receivables --help
```

## 目录与数据

receivables/ 保存领域逻辑和请求入口，tests/ 包含正常行为、边界与恢复测试。例子中的标识和记录为合成资料，不包含真实人员或生产测量。业务目录和本地数据库由调用者指定，应与源码分开保存。

## 干净环境复现

容器定义固定运行时版本。构建时准备环境，运行时无需网络；每次启动会复制只读源码到临时工作目录，测试产生的文件不会写回仓库。

```sh
docker build -t local-product-check .
docker run --rm --network none local-product-check
```
